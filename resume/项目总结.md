# 项目总结（第一人称，约 600 字）

这个项目是我为求职准备的运动控制系统作品集：用 Python 在没有真实驱动器的条件下，完整仿真了"龙门双轴同步 + 电子凸轮飞剪"这两类最典型的多轴运动控制场景。

做这个项目的起点是一个问题：**龙门两侧的伺服轴为什么会不同步？** 我从位置环的基本方程推导出恒速下跟随误差 e = v/Kp——两台电机的位置环增益由编码器、丝杠导程和驱动器参数共同决定，天然存在几个百分点的不一致，于是各自的跟随误差不同，同步偏差 Δ = v/Kp1 − v/Kp2 就出现了。为了让这个机理在代码里"真实发生"，我把虚拟伺服轴做成与真实系统同构的结构：梯形/S 曲线规划器生成指令，一阶闭环模型产生滞后，脉冲当量量化指令，负载扰动和增益都可以按轴独立配置。自测时恒速跟随误差精确等于 v/Kp，验证了模型的正确性。

同步方案我选择了交叉耦合同步：把两轴实际位置的差值 Δ 对称反馈到两轴目标上。我推导了稳态偏差公式 Δ* = v(1/Kp2 − 1/Kp1)/(1 + 2Kcc)，说明补偿能把偏差压缩为开环值的 1/(1+2Kcc)。批量实验跑了补偿开/关 × 失配 5%~30% 共八种组合，实测 P95 同步偏差全部下降约 80%，与理论完全吻合；还做了安全联锁演示——30% 失配加 2mm 阈值时无补偿会触发报警停机，有补偿则正常完成。

电子凸轮部分，我按飞剪工艺自动生成 256 点凸轮表：待机→加速追赶→与带速同步（落刀）→快速返回。关键推导是表中同步段斜率必须等于定长 L，这样刀的水平速度才等于带速。运行时线性插值跟随，支持在周期边界切换凸轮表模拟换产。带速扫描实验中，700mm/s 带速下同步段速度误差均值只有 0.65mm/s，循环节拍与理论值 L/v 的偏差小于 1ms。

最后我用 Flask + ECharts 做了在线看板，可以实时改失配度和补偿开关看曲线变化，并用 Canvas 做了输送带与切刀联动的动画。整个项目所有指标都诚实标注"仿真验证值"，但控制思想与真实系统完全一致——我也整理了真机上还需要做的驱动器整定工作，清楚仿真与工程的边界在哪里。
